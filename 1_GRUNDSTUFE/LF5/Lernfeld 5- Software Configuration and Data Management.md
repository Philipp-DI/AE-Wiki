# Lernfeld 5: Software Configuration and Data Management

## 📜 Overview & Relevance:

This module guides you through the complete Software Development Life Cycle (SDLC). Software development is much more than just typing code; it is a structured process. You will learn how to analyze unstructured data, design system architectures using analog modeling techniques (UML, ERM), set up professional development environments (Git, IDEs), write foundational code, debug it, and finally compare how different project management frameworks (agile vs. classic) organize this exact process.

## **🏆** **Core Competencies (Main Learning Objectives):**

- Analyze unstructured data sets and derive clear customer requirements. (K4)
- Design system architectures and logic using analog UML 2.0, PAP, and ER models. (K3)
- Set up and operate professional development tools, IDEs, and Version Control Systems like Git. (K3)
- Compare programming paradigms and implement basic algorithms. (K4)
- Execute software testing and debugging methodologies to ensure quality. (K3)
- Evaluate and contrast classic (Waterfall, V-Model) and agile (Scrum, Kanban) SDLC frameworks. (K6)

## 🎭 The 3 Elective Scenarios (The Context)

Your team will choose **one** of these three fictional companies at the beginning. You will accompany this company through all the epics of this learning field.

### Scenario A: Neustadt Museum

The local museum has decades of historical artifact records stored in dusty ledgers, loose papers, and index cards. They urgently need to digitize their inventory, but the data is highly unorganized and inconsistent.

### Scenario B: Mutti's Recipe Collection

A beloved traditional bakery wants to scale its business, but all core recipes exist on hundreds of handwritten, stained notes. Measurements vary wildly (from grams to "a pinch"). The kitchen staff needs a standardized digital solution.

### Scenario C: Metropolis Library

A large city library's legacy management software crashed permanently. Currently, they are surviving on chaotic Excel sheets to track thousands of books and member loans. They need a robust, relational data concept and a new prototype.

## 🗺️ Our Learning Journey (Epics)

### 5.1: Requirements & Analysis

Transforming chaos into structure: We will conduct simulated customer interviews, analyze unstructured analog data, and write a formal requirements specification.

### 5.2: System Design & Modeling

Visualizing the solution offline: Before touching a keyboard, we will model the system architecture using ER-Models, Flowcharts (PAP), and UML 2.0 diagrams on whiteboards and paper.

### 5.3: Development Tools & Version Control

Setting up the workshop: We will understand the difference between text editors and IDEs, explore compilers vs. interpreters, set up Git/GitHub, and learn about workflow models like Git-Flow.

### 5.4: Implementation & Paradigms

Writing the logic: We will compare top programming languages and paradigms (OOP, functional, procedural), write foundational Python/Bash code, and explore deployment concepts using Docker.

### 5.5: Testing, Debugging & Acceptance

Ensuring quality: We will dive deep into debugging by setting breakpoints, writing test cases, exploring basic CI/CD concepts with GitHub Actions, and preparing for final customer acceptance.

### 5.6: SDLC Frameworks & Methodologies

Connecting the dots: We will conclude by comparing how different methodologies (Waterfall, Spiral, V-Model, XP, Kanban, Scrum) guide a team through the phases we just experienced.
