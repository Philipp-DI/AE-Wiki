# LF5.6.4: Continuous Flow (Kanban & XP)

## 👤 User Story

> As an Agile Coach,  
> I want to compare Kanban and eXtreme Programming (XP),  
> so that I can optimize team workflow using WIP limits and strict engineering practices.

## 🎉 Celebration Criteria (Learning Objectives)

- **I can define** the purpose of WIP (Work In Progress) limits in Kanban. (K1)
- **I know how to differentiate** Kanban's continuous flow from Scrum's timeboxed Sprints. (K2)
- **I can explain** core XP engineering practices like Pair Programming and TDD. (K2)

## 🧠 Knowledge Briefing

Scrum is not the only agile framework. Other methods focus on different aspects of development.

**1\. Kanban (Visual Flow):** Originating from Toyota's manufacturing process. It visualizes the workflow on a board.

- _No Sprints:_ Work flows continuously.
- _WIP Limits (Work In Progress):_ The most important rule. You limit how many tasks can be in the "In Progress" column at once (e.g., max 3). This forces the team to _finish_ old tasks before starting new ones. ("Stop starting, start finishing").

**2\. eXtreme Programming (XP):** Focuses heavily on technical excellence and engineering practices.

- _Pair Programming:_ Two developers share one screen and one keyboard. One types, the other reviews in real-time. High quality, zero knowledge silos.
- _Test-Driven Development (TDD):_ You write the automated Unit Test _before_ you write the actual code. The code is written just to make the test pass.

## ⚠️ Common Pitfalls

- Using a Kanban board without setting WIP limits. Without WIP limits, it's just a wall with sticky notes, not a Kanban system. WIP limits create the crucial "pull" effect.

## 🛠️ Mandatory Tasks (K1 - K3)

1. Explain the primary goal of setting "WIP Limits" in a Kanban system. (K2)
2. Differentiate between Kanban and Scrum regarding the concept of fixed-time "Sprints". (K2)
3. Draw a simple analog Kanban board with 4 columns (To Do, Doing, Review, Done) and assign a WIP limit of "2" to the "Doing" column. (K3)
4. Define "Pair Programming" in the context of eXtreme Programming (XP). (K1)
5. Explain the sequence of steps in Test-Driven Development (TDD) (e.g., Red-Green-Refactor). (K2)

## 🔥 Optional Tasks (K4 - K6)

1. Analyze the psychological resistance a traditional management team might have against implementing Pair Programming ("paying two people to do one job"). (K4)
2. Evaluate how reaching a WIP limit in a Kanban column acts as an early warning system for organizational bottlenecks. (K5)
3. Formulate a hybrid "Scrumban" process for an IT Support Helpdesk that needs to handle both planned projects and urgent daily tickets. (K6)
