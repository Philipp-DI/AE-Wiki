# LF5.6.1: Classic Approaches (Waterfall & Spiral

## User Story

As a Project Manager, **I** want to understand the Waterfall and Spiral models, so that **I** know when to apply linear planning and when to prioritize iterative risk management.

## Celebration Criteria

- **I can define** the strict, linear phases of the Waterfall model. (K1)
- **I know how to illustrate** the risk-driven approach of Boehm's Spiral model. (K2)
- **I can explain** the inflexibility of classic models regarding changing customer requirements. (K2)

## Knowledge Briefing

Before "Agile" existed, software was built like a house: plan everything, then build everything.

**1\. The Waterfall Model:** A linear, sequential approach. You cannot move to the next phase until the current one is 100% finished.

- _Phases:_ Requirements -> Design -> Implementation -> Testing -> Deployment -> Maintenance.
- _Pros:_ Easy to manage, clear documentation, fixed budgets.
- _Cons:_ Highly inflexible. If the customer changes their mind during the testing phase, going back to the design phase is extremely expensive.

**2\. The Spiral Model (Barry Boehm):** Combines linear development with iterative risk analysis.

- Loops through four main quadrants: 1. Determine objectives, 2. Identify and resolve risks, 3. Develop and verify, 4. Plan the next iteration.
- _Focus:_ Used for massive, high-risk projects (e.g., aerospace, military software) where a failure is catastrophic.

## Common Pitfalls

- Assuming the Waterfall model is "dead" or always bad. For projects where requirements are 100% fixed by law or physics (like building bridge-control software), Waterfall is still highly effective.

## Mandatory Tasks

1. List the 6 standard phases of the Waterfall Model in their correct chronological order. (K1)
2. Explain why the Waterfall model is often compared to building a physical house. (K2)
3. Describe the main drawback of the Waterfall model if a customer changes their requirements late in the project. (K2)
4. Identify the primary focus of the Spiral Model compared to the Waterfall Model. (K1)
5. Draw a simple analog sketch of the Spiral Model, labeling the 4 main quadrants. (K3)

## Optional Tasks

1. Analyze a historical software failure (e.g., a massive government IT project) and trace how a strict Waterfall approach contributed to the disaster. (K4)
2. Evaluate a scenario (e.g., programming a pacemaker) where using the Spiral model is vastly superior to a fast, agile approach. (K5)
3. Design a modified Waterfall process that includes small "feedback loops" between the Design and Implementation phases to mitigate risk. (K6)
