## 🧠 Wissens-Briefing

Nicht jedes LGS geht glatt auf.

- **Fall A (Eindeutig):** Stufenform perfekt ( $x=... , y=... , z=...$). Idealfall.
- **Fall B (Widerspruch - Keine Lösung):** In einer Zeile entsteht $0x + 0y + 0z = 5$ (also $0=5$). Das ist unmöglich.
  - _Bedeutung:_ Die Anforderungen widersprechen sich (z.B. "Billig, Schnell, Hohe Qualität" ist oft unmöglich).
- **Fall C (Unendlich Lösungen):** Eine Zeile wird zur "Nullzeile" ( $0=0$). Wir haben weniger Gleichungen als Variablen.
  - _Bedeutung:_ Wir haben Freiheitsgrade. Wir können $z = t$ (Parameter) setzen und $x, y$ in Abhängigkeit von $t$ ausdrücken.

## ⚠️ Typische Fallstricke

- **Computer-Absturz:** Ein naiver Algorithmus teilt durch 0 oder läuft in eine Endlosschleife, wenn er Fall B oder C nicht abfängt.
- **Rundungsfehler:** Im Computer ist $0.000000001$ oft nicht $0$ . Das kann zu falschen "eindeutigen" Lösungen führen (Numerische Instabilität). → round() in python to avoid

#### P1: Diagnose (Analog): Du wendest Gauß an und erhältst in der letzten Zeile: $0 \* x3 = 7$. Was bedeutet das für das LGS? (K2)

Das hieße 0 = 7, was mathematisch eine falsche Aussage darstellt. Demnach haben wir für dieses Gleichungssystem **keine Lösung**.

#### P2: Freiheitsgrade (Analog): Du erhältst in der letzten Zeile $0 = 0$. Du hast 3 Variablen, aber effektiv nur 2 Gleichungen. Wähle $x_3 = t$ und drücke $x_1$ und $x_2$ mit Hilfe von $t$ aus. (K3)

**Annahme:** Nach der Gauß-Elimination verbleibt:

- $I: 4x_1 + 2x_2 + 2x_3 = 6$
- $II: 6x_2 - 3x_3 = 3$
- $III: 0 = 0$
- $x_3 = t$ (freier Parameter, $t \\in \\mathbb{R}$)

Zu $II: 6x_2 - 3t = 3 \\quad|\\div3=> 2x_2 - t = 1​\\quad |\\div2, \\quad +t=> \\mathbf{x_2 = 0,5+\\frac{1}{2}t}$

Zu $I: 4x_1 + 2(0,5+\\frac{t}{2}) + 2t = 6\\quad |\\div2 => 2x_1+0,5+\\frac{t}{2}+t=3\\quad |\\div2 =>x_1+0,25+\\frac{t}{4}+\\frac{t}{2} =1,5\\quad| => \\mathbf{x_1 = 1,25-\\frac{3}{4}t}$

**Lösungsmenge:**

$\\vec{x} = \\begin{pmatrix} 1,25 \\\\ 0,5 \\\\ 0 \\end{pmatrix} + t \\cdot \\begin{pmatrix} -0,75 \\\\ 0,5 \\\\ 1 \\end{pmatrix}, \\quad t \\in \\mathbb{R}$

**Zweierlei Tests:**

$t=2=>\\begin{pmatrix} 1,25 \\\\ 0,5 \\\\ 0 \\end{pmatrix} + \\begin{pmatrix} -1,5 \\\\ 1 \\\\ 2 \\end{pmatrix}=\\begin{pmatrix} -0,25 \\\\ 1,5 \\\\ 2 \\end{pmatrix}$ Einsetzen: $I: -1 + 3 + 4 = \\mathbf{6}\\quad II: 9 - 6 = \\mathbf{3}$

$t=5=>\\begin{pmatrix} 1,25 \\\\ 0,5 \\\\ 0 \\end{pmatrix} + \\begin{pmatrix} -3,75 \\\\ 2,5 \\\\ 5 \\end{pmatrix}=\\begin{pmatrix} -2,5 \\\\ 3 \\\\ 5 \\end{pmatrix}$ Einsetzen: $I: -10 + 6 + 10 = \\mathbf{6}\\quad II: 18 - 15 = \\mathbf{3}$

Für jedes $t$ erhält man eine gültige Lösung - also unendlich viele.

<details>
<summary>How to build such a system:</summary>

**Wie baut man ein solches System von Grund auf "sauber"?**

Der zuverlässigste Weg ist, **von der Lösung auszugehen**, nicht von den Gleichungen. So:

**Schritt 1** - Lösungsmenge festlegen. Wähle einen Basisvektor und einen Richtungsvektor frei:

$\\vec{x} = \\begin{pmatrix} 1 \\\\ 2 \\\\ 0 \\end{pmatrix} + t \\cdot \\begin{pmatrix} 1 \\\\ -1 \\\\ 1 \\end{pmatrix}$​​

**Schritt 2** - Zwei konkrete Lösungen einsetzen (z.B. $t=0$ und $t=1$), um zwei Gleichungen zu erzeugen, die du kontrollierst.

**Schritt 3** - Koeffizienten der Gleichungen so wählen, dass beide Punkte sie erfüllen. Die dritte Gleichung ist dann einfach eine Linearkombination der ersten beiden - sie wird zu $0=0$.

</details>

#### P3: Geometrie (Analog): Zwei Geraden im 2D-Raum können sich schneiden (1 Lösung). Welche Lage haben sie bei "0 Lösungen"? Welche bei "unendlich Lösungen"? (K3)

| Anzahl Lösungen | Geometrische Lage der Geraden |
| --- | --- |
| Genau 1 | Die Geraden **schneiden** sich **in einem Punkt** (unterschiedliche Steigungen) |
| 0 Lösungen | Die Geraden sind **parallel** - gleiche Steigung, aber verschiedene y-Achsenabschnitte |
| Unendlich viele | Die Geraden sind **identisch** - eine Gleichung ist ein Vielfaches der anderen |

#### P4: Szenario-Check: Ein Kunde will aus 2 Rohstoffen (A, B) eine Mischung herstellen, die 100g Protein und 0g Fett enthält. Rohstoff A hat Fett, Rohstoff B auch. Warum wird das LGS wahrscheinlich "keine Lösung" liefern? (K3)

Der Plan bringt einen **Widerspruch**: Man kann nicht gleichzeitig Protein maximieren und Fett auf 0 setzen, wenn jeder Rohstoff Fett enthält.

Jeder der beiden Koeffizienten wäre in diesem Szenario $\>0$. Das Ziel würde jedoch bedeuten, dass beide mit einer Menge multipliziert $0$ ergeben. Da wir keine negative Menge benutzen können, wäre die einzige Möglichkeit KEINE Rohstoffe zu nutzen, um auf 0-Fett zu kommen - dann fehlt allerdings natürlich jegliches Protein.

#### P5: Python-Exception: Welche Python-Fehlermeldung erwartest du, wenn du versuchst, ein unlösbares System mit einer Standard-Funktion zu lösen? (K2)

Bei `numpy.linalg.solve(A, b)` mit einem singulären (nicht invertierbaren) System wirft NumPy:

`numpy.linalg.LinAlgError: Singular matrix`

Das bedeutet: Die Koeffizientenmatrix $A$ ist singulär - Determinante = 0, somit nicht invertierbar, und das System hat _entweder keine oder unendlich viele Lösungen_.

Eine eigene Implementierung ohne entsprechend implementierten Check würde stattdessen einen `ZeroDivisionError` werfen, wenn der Algorithmus versucht, durch ein Null-Pivot zu teilen.

#### Z1: Schreibe eine Python-Funktion, die det(matrix) (Determinante) berechnet (fur 2x2). Was sagt die Determinante über die Lösbarkeit aus? (K4)

```python
def det_2x2(matrix_quad_2):
    a, b = matrix_quad_2[0]
    c, d = matrix_quad_2[1]
    det = a * d - b * c
    return det

# Beispiel:
A = [[2, 3], [1, 4]] # 2*4 - 3*1 = 5

# Singuläre Matrix (parallele Geraden):
B = [[2, 4], [1, 2]] # 2*2 - 4*1 = 0
```

**Was sagt die Determinante?**

- $\\det(A) \\neq 0$ : Matrix ist invertierbar → LGS hat **genau eine** Lösung.
- $\\det(A) = 0$: Matrix ist singulär → LGS hat **keine oder unendlich viele** Lösungen.

**Analogie**: Die Determinante misst, wie sehr die Matrix "verzerrt" ist - bei 0 wird der Raum auf eine Linie oder einen Punkt "zusammengefaltet", so kann man nicht mehr eindeutig “zurückrechnen”.

#### Z2: Konstruiere ein LGS mit 3 Variablen, das unendlich viele Lösungen hat, und gib die Lösungsmenge an. (K5)

> “Ein LGS hat unendlich viele Lösungen, wenn eine Gleichung eine **Linearkombination** der anderen ist - sie fügt keine neue Information hinzu.”

**Konstruktion:** _Gleichung III = Gleichung I + Gleichung II_

$I: x_1 + x_2 + x_3 = 6$

$II: x_1 - x_2 + x_3 = 2$

$III: 2x_1 + 0x_2 + 2x_3 = 8$( $\= I + II$ → keine neue Info)

Nach Gauß-Elimination entsteht in Zeile III: $0=0$. Man hätte also auch das LGS aus P2 nehmen können.

Wie in P2 durchgeführt:

$I: 2x_1 + 2x_3 = 8 \\quad => x_1 + x_3 = 4 \\quad => x_1 = 4 - x_3$​

$II: 2x_2 = 4 \\quad => x_2 = 2$

$x_3​=t$:

$\\begin{pmatrix} 4 - t \\\\ 2 \\\\ t \\end{pmatrix}\\quad, t \\in \\mathbb{R}$​

#### Z3: Diskutiere: Warum ist "Überbestimmtheit" (mehr Gleichungen als Variablen) in der Data Science (Regression) der Normalfall und wie geht man damit um? (Stichwort: Kleinste Quadrate) (K5)

KI-generierte Lösung:

:::warning
In der Praxis hat man typischerweise viel mehr Datenpunkte (Gleichungen) als Modellparameter (Variablen) - z.B. 10.000 Messwerte, aber nur 3 Koeffizienten einer Regressionsgeraden. Das System $A \\cdot \\vec{x} = \\vec{b}$ ist dann **überbestimmt** und hat im Allgemeinen keine exakte Lösung, weil die Daten verrauscht sind.

Der Ausweg: **Methode der kleinsten Quadrate (Least Squares)**. Statt eine exakte Lösung zu suchen, minimiert man den **quadratischen Fehler**:

$\\min_{\\vec{x}} \\| A \\cdot \\vec{x} - \\vec{b} \\|^2$

Die Lösung dieser Optimierung ergibt die **Normalengleichungen**:

$A^T A \\cdot \\vec{x} = A^T \\vec{b}$

In Python: `numpy.linalg.lstsq(A, b)` - das ist die Grundlage jeder linearen Regression.
:::
